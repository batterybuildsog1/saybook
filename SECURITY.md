# Security and privacy boundaries

Self mode is a single-family workspace. An optional passcode gates its data and media; an unset passcode intentionally makes it accessible without authentication. The passcode-derived cookie is HttpOnly, Secure and SameSite=Strict. Cross-origin writes are rejected. Choose a strong passcode, keep Worker secrets private, and restrict account/dashboard access. This is not a substitute for individual parent accounts.

Hosted mode authenticates the parent before core routes, requires recorded consent plus a verified paid Checkout before child content is accepted, and requires explicit permission for saved own-reading recordings. Writer changes and sharing require a recent parent authorization. Account/billing routes remain available before child access. The Hosted module owns authentication, billing, retention and allowance enforcement; see `docs/HOSTED.md` and `docs/OPERATOR.md` for its launch status.

Every core app table carries account_id. Stories use `(account_id,id)` and scenes `(account_id,story_id,sid)`. SQL predicates bind the account, including both sides of the event/story join. R2 objects are physically under `accounts/<account_id>/`; the scoped adapter applies that prefix to every operation. Queue messages carry an account ID, not credentials. Hosted queue consumers verify active consent before working. Creation and settings writes are conditional on an active, verified account; scene/share inserts require a live parent story. R2 saves recheck account/story state before and after writing, and delete a just-written object if deletion raced it. Hosted retention runs through its lazy scheduled handler at 09:00 UTC daily.

Shared books use a revocable bearer capability with 192 random bits. Hosted link creation also requires `disclosure_consent:true` and the current `notice_version`, separate from the parent password. A scoped, versioned `hosted_consent` record is inserted atomically before the share; revocation is recorded too. Hosted public readers require that durable choice and an active, verified account. Parent-approved links expose only page text, current illustrations, and existing per-page audio caches; authors are hidden by default. Public reads never generate pictures, speech or model requests. Shared JSON/media are no-store and noindex, and only explicitly referenced keys are served. Revocation and story deletion remove access; they cannot recall a copy someone already downloaded.

Provider calls check allowance immediately before each attempt. Text usage reads separate input/output counts, image calls count attempts even on failure, and TTS records synthesized characters and provider credits where supplied. Unknown billable outcomes consume conservative usage instead of becoming free. Limits stop provider work; hosted provider limits latch a global breaker and terminal queue messages are acknowledged without retries. Streaming holds settle after upstream completion before unused holds are released. Prices use configured tariffs and should be reconciled with invoices; subscription-backed hosted text/images are configured at zero marginal USD, with image/token limits retained.

Dictation audio is transient in this app; saved own readings and uploads are persistent R2 objects until deletion or hosted retention. Provider and browser/OS speech retention are separate. Analytics is off by default. A separate configured project and device-level parent opt-in are required; public landing and shared-reader surfaces never collect telemetry.

## Verification and reporting

Run the E2E scripts only against isolated resources you control. They create synthetic data and may spend provider usage. Test reports and media remain outside the public tree. The hosted fixture controls require test Stripe mode, an explicit flag and an independent secret token; live Stripe mode disables them. Always disable and remove test controls after verification.

OpenAI TTS fallback is implemented but has not been verified against a live speech endpoint in the launch test environment. Provider retention and operator-specific legal duties require separate verification; see [operator responsibilities](docs/OPERATOR.md).

Report a suspected vulnerability privately to the deployment operator. Never attach a child’s story, recording, passcode or provider key to a public issue.
